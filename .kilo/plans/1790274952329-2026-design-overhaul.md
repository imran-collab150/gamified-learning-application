# Plan: 2026 Design Overhaul (Multi-Device Responsive Redesign)

## Overview
Revamp the gamified learning platform to fully comply with the multi-device responsiveness spec in `agents.md`. Currently the app uses a hybrid of Tailwind utility classes and custom CSS `@media` rules that conflict. The sidebar overlay only works on `lg:` (desktop), bottom nav is never rendered on mobile, and the desktop 3-column dashboard is incomplete.

## Current State Analysis
- **App.tsx**: Static `page` state, no route transitions, no bottom nav rendered
- **Header.tsx**: Hamburger button only `lg:hidden` — wrong, should be visible on phone/tablet
- **SidebarNav.tsx**: Overlay on `lg:hidden` — should be overlay on phone only; collapsible rail on tablet
- **CSS**: Has both `lg:grid-cols-*`, `sm:grid-cols-*`, AND custom `.stats-row`, `.community-grid` classes — conflicting rules
- **Bottom Nav**: Defined in `BottomNav.tsx` but never imported/rendered anywhere
- **Home.tsx**: Uses `main-content` class but no bottom nav for mobile, no right panel for desktop
- **Missing**: `<RightPanel>` with live leaderboard/profile, `document.startViewTransition()` for route navigation

## Design Decisions

### Breakpoint Strategy
Use Tailwind's built-in breakpoints exclusively (remove custom CSS `@media` classes):
- `DEFAULT` (phone): `< 640px`
- `sm` (large phone): `640px`
- `md` (tablet): `768px`**
- `lg` (tablet/desktop): `1024px`
- `xl` (desktop): `1280px`

**Note**: The spec says tablet is `640px - 1024px`. Tailwind's `md` (768px) falls in this range. We'll use:
- Mobile: default (`sm:hidden`, `md:flex`)
- Tablet: `md:` through `lg:` (`lg:hidden`, `xl:flex`)
- Desktop: `lg:` and up

### Component Architecture
- **App.tsx**: Wrap in `BrowserRouter`, use `useViewTransition` for route changes
- **SidebarNav**: 
  - Phone: overlay (slide-in from left)
  - Tablet: collapsible rail (icon-only by default, expand on hover)
  - Desktop: always expanded left sidebar
- **BottomNav**: Phone only (`lg:hidden`)
- **RightPanel**: Desktop only (`lg:block`), collapsible

## Risks & Mitigations

| Risk | Mitigation |
|------|-----------|
| CSS conflicts between Tailwind and custom classes | Audit all component classes, remove custom CSS equivalents |
| Sidebar visibility on tablet breaks | Test `md:block` + `lg:hidden` logic carefully |
| `startViewTransition` not supported on Safari | Feature detection with fallback |
| Build fails with strict unused vars | Audit all imports/components |

## Validation Plan
1. `npm run build` compiles without errors
2. CSS size < 20 kB gzip (current 3.82 kB → expected 5-8 kB)
3. No conflicting CSS rules (grep for duplicate definitions)
4. Sidebar renders correctly on all 3 viewport sizes
5. Bottom nav only shows on phone
6. Right panel only shows on desktop
7. All components use `min-h-[48px] min-w-[48px]` for touch targets
8. `document.startViewTransition()` wraps route changes
